# Contributing

The notes live in `Vault/`. Everything else in this repo is [Quartz](https://quartz.jzhao.xyz), the static-site generator that publishes the vault to <https://theosdoor.github.io/em-knowledge-base>.

## First-time setup

```sh
git clone https://github.com/Theosdoor/em-knowledge-base.git
cd em-knowledge-base
npm ci
npx quartz plugin install
```

Then in Obsidian: **Open folder as vault** → pick `em-knowledge-base/Vault`. The `.obsidian` settings are committed, so you get the same graph colours and enabled plugins as everyone else.

You only need `npm ci` if you want to preview the site locally. If you are just writing notes, Obsidian and git are enough.

## Day-to-day

We all push straight to `main`. No branches, no PRs. One paper per file keeps conflicts rare, but:

```sh
git pull --rebase        # ALWAYS before you start editing
# ... edit in Obsidian ...
git add -A && git commit -m "add Zhao 2026 piggyback note"
git push
```

Every push to `main` rebuilds and redeploys the site (~2 min). Check the Actions tab if it doesn't appear.

If you get a conflict, it will be inside one note. Resolve it in a text editor — the frontmatter is plain YAML and the body is plain Markdown.

## Adding a paper

Copy `Vault/Templates/Paper Note.md` (Obsidian: `Ctrl`/`Cmd` + `P` → *Insert template*) into `Vault/Papers/`.

**Filename is the citekey**: first author's surname in lowercase + the first significant word of the title + year. Skip leading articles.

| Paper                                                    | Citekey             |
| -------------------------------------------------------- | ------------------- |
| Zhao et al., *The Piggyback Hypothesis…*, 2026            | `zhaoPiggyback2026` |
| Soligo et al., *Emergent Misalignment is Easy…*, 2026     | `soligoEmergent2026`|
| Wang et al., *From Data to Behavior…*, 2026               | `wangData2026`      |

Put the same citekey in `tags`, and a readable `Author Year — Short Title` in `aliases` so search and autocomplete stay usable.

Fill what you know. Leave `> [!todo] Not yet filled in` in the sections you don't — a visible gap is better than a silent one.

## Linking papers

Papers are the nodes in the graph. Edges come from the `## Related Papers` section, and **every edge needs a reason**:

```markdown
- [[zhaoPiggyback2026|Zhao 2026 — The Piggyback Hypothesis]] — both argue narrow
  finetuning re-activates existing structure rather than teaching something new.
  Zhao localises the carrier to the chat-template prefix; Soligo characterises
  the general solution's stability.
```

A bare `[[link]]` with no explanation is worse than no link — it makes the graph look connected without telling anyone why.

**Add the mirror bullet on the other note too**, phrased from that paper's point of view. The backlinks panel on each page will show you any you missed.

## Status and provenance

Set `status` honestly:

- `stub` — metadata and links only, not read properly
- `ai-drafted` — summary generated by Opus 5, unverified
- `in-review` — you are checking it against the paper right now
- `human-reviewed` — checked; put your name in `reviewed-by`

Sections drafted by Opus 5 carry an inline `*Opus 5*` marker. When you verify a section against the paper, delete the marker and update `status` / `reviewed-by`.

## Previewing the site

```sh
npm run serve     # http://localhost:8080, hot-reloads as you edit
npm run build     # one-off build into public/
```

Both pass `-d Vault` to Quartz. Plain `npx quartz build` will look in `content/` and find nothing.

## Images

Put them in `Vault/Assets/` and embed with `![[filename.png]]`. Name them after the paper: `minegishi-2026-feature-geometry.png`.

## What not to commit

`.gitignore` handles `node_modules/`, `public/`, `.quartz/` and Obsidian's per-machine `workspace.json`. The rest of `.obsidian/` is shared on purpose — if you change a setting everyone gets it, so mention it.

`Archive/` holds the original Google Docs megadoc this vault was split out of. Leave it alone; it is there for provenance, and it is excluded from the published site.

## Updating Quartz

We track Quartz v5.0.0 with its own history removed. To move to a newer version, clone the upstream repo at the new tag and copy `quartz/`, `package.json`, `package-lock.json` and `quartz.lock.json` over, then re-run `npm ci && npx quartz plugin install`. Diff `quartz.config.default.yaml` against our `quartz.config.yaml` for new options.
